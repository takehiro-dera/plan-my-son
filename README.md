# ひなたの予定（ヒーロー版・配布セット）

iPad で「今日の予定を見て、できたらエネルギーをチャージ（タップ）する」ためのアプリです。
予定は保護者が `plans.json` で管理し、iPad は表示とチェックだけを行います。

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体（このファイルは基本いじりません） |
| `plans.json` | **予定・ごほうびの設定。ここを更新します** |
| `manifest.webmanifest`, `icon-*.png` | ホーム画面に追加したときのアイコンと表示設定 |
| `sync/Code.gs`, `sync/SYNC_SETUP.md` | 同期用スクリプトと設定手順（**GitHub には上げません**） |

`plans.json` には、現在の予定・ごほうび・ボーナスが入っています。予定を変えるときは「5. 予定を更新する流れ」を見てください。

## ヒーローと曜日

曜日の漢字（日・月・火・水・木・金・土）にあわせて、7人のオリジナルヒーローが交代で登場します。見ている曜日のヒーローの色に、画面全体の色が変わります。

| 曜日 | ヒーロー | 色 |
|---|---|---|
| 日 | サン | オレンジ |
| 月 | ムーン | シルバー（画面はあい色） |
| 火 | ファイア | あか |
| 水 | アクア | あお |
| 木 | リーフ | みどり |
| 金 | ゴールド | きいろ |
| 土 | ロック | ブロンズ |

## 1. GitHub Pages で公開する

1. GitHub で新しいリポジトリを作ります（**Public**。無料プランで Pages を使えるのは公開リポジトリです）。他のアプリとは別のリポジトリにします。
2. このフォルダの中身のうち、`sync/` 以外（`index.html`、`plans.json`、`manifest.webmanifest`、`icon-*.png`、`README.md`）をアップロードします（Add file → Upload files）。
3. リポジトリの Settings → Pages で、ブランチ（main）とフォルダ（/ root）を選んで保存します。
4. 数分待つと、`https://（ユーザー名）.github.io/（リポジトリ名）/` で開けるようになります。

※ 画面の表記は GitHub 側の更新で変わることがあります。

**公開に関する注意**：サイトも `plans.json` も、URL を知っている人は誰でも見られます。名前・学校名・住所などは入れないでください。

## 2. iPad に入れる

1. iPad の Safari で上の URL を開きます。
2. 共有ボタン →「ホーム画面に追加」。
3. **以後はホーム画面のアイコンから開きます。**
   Safari のタブで開いたままだと、7 日間使わないと保存データ（ポイントなど）が消える仕様があるためです。ホーム画面に追加したアプリは対象外です。
4. Safari で開いたときとホーム画面から開いたときでは、保存データが別になることがあります。最初からホーム画面のアイコンで使い始めるのが安全です。

## 3. 画面の使い方

- 今日の曜日の予定をタップ（または円グラフをタップ）すると達成。予定が全部できると **1 ポイント**（1 日 1 回まで）。
- 他の曜日は見るだけです（その日になるまで押せません）。
- 右上の ⚙️ を **0.7 秒ほど長押し**すると「おうちの方へ」画面が開きます。
  - 予定ファイルの状態確認と「いま更新する」
  - ポイントの ±1 補正・0 に戻す
  - ごほうびを渡したらチェック
  - バックアップ（書き出し・コピー・読み込み）

## 4. plans.json の書き方

```json
{
  "version": 1,
  "updatedAt": "2026-11-08",
  "weekly": {
    "1": {
      "range": ["15:00", "21:00"],
      "tasks": [
        { "id": "snack",  "name": "おやつ",   "icon": "🍪", "start": "15:00", "end": "15:30" },
        { "id": "lesson", "name": "ピアノ",   "icon": "🎹", "start": "15:30", "end": "16:30" }
      ]
    }
  },
  "overrides": {
    "2026-11-17": {
      "range": ["15:00", "21:00"],
      "tasks": [
        { "id": "homework", "name": "しゅくだい", "icon": "📝", "start": "15:30", "end": "16:15" }
      ]
    }
  },
  "rewards": [
    { "id": "r1", "pts": 5, "name": "すきな おやつ", "icon": "🍦" }
  ]
}
```

（上は書き方の例です。実際のファイルには `weekly` の "0"〜"6" をすべて入れます。）

- `weekly`：基本の週間プラン。キーは曜日の番号（`"0"`=日, `"1"`=月, … `"6"`=土）。
- `overrides`：**特定の日だけ**予定を置き換えます。キーは `YYYY-MM-DD`。予定を空にしたい日は `"tasks": []`。
- `range`：円グラフの範囲。省略すると平日 15:00〜21:00、土日 07:00〜21:00。
- `tasks`：`id`（その日の中で重複しない）、`name`、`icon`（絵文字）、`start` / `end`（`HH:MM`）、`memo`（任意。予定の下に小さく出る補足。例：「プリント2まい」）。
  予定どうしは重ならないこと、`range` の内側に入っていることが必要です。
- `rewards`：ごほうび。`pts` は 1〜999 の整数。**累計ポイントが `pts` に届くと「ゲット！」になります**（ポイントは減りません）。
- `updatedAt`：更新日。画面の一番下に表示されるので、反映されたかの確認に使えます。

### 守ってほしいルール
- **既存の予定の `id` は変えないでください。** 達成の記録は「日付＋id」で残っています。変えると、その日の達成が外れます。
- 形式に誤りがあると、アプリは**前の予定を使い続け**、「おうちの方へ」画面にエラー内容を表示します。

## 5. 予定を更新する流れ

1. Claude に、現在の `plans.json` を貼り付けて、変更内容を伝えます。
   例：「来週 11/17（火）はスイミングが休み。代わりに 15:30〜16:30 を『えいがの じかん』にして。id は既存のものを変えず、updatedAt は今日にして。plans.json 全体を返して」
2. 返ってきた内容で、GitHub の `plans.json` を置き換えます（ファイルを開く → 鉛筆アイコン → 貼り替え → Commit changes）。
3. iPad でアプリを開き直す（またはアプリに戻る）と取得します。反映に少し時間がかかることがあります。すぐ確認したいときは「おうちの方へ」画面の「いま更新する」を押します。

通信できないときは、最後に取得できた予定を表示します。

## 6. データの保存場所

| データ | 保存場所 |
|---|---|
| 予定・ごほうびの設定 | GitHub の `plans.json`（iPad は取得して端末にも保存） |
| 達成の記録・ポイント・「もらった」チェック | **iPad の中**（同期を設定した場合は、スプレッドシートにも送ります） |

ポイントは iPad にしかありません（同期を設定した場合は、スプレッドシートにも残ります）。ときどき「おうちの方へ」画面で**書き出して**、メモなどに保存しておくと安心です。

## 7. 同じ iPad で複数のアプリを使う場合（保存キーの分離）

このアプリは、保存キーを次の2つで分けています（保護者画面の「保存先」で確認できます）。

- アプリ固有の名前（`kids-schedule-son-v1`）
- ページの場所（URL のパス）

そのため、同じ iPad・同じブラウザで別の予定アプリを開いても、記録は混ざりません。バックアップもこのアプリ専用の形式なので、別のアプリのバックアップは読み込めません。

- **リポジトリ名やフォルダ名を変えると、保存先も変わり、記録が引き継がれません。** 名前は変えない運用にしてください（変えるときは先にバックアップを書き出してください）。
- `index.html` の `MIGRATE_LEGACY` は `false` にしてあります。旧バージョンの保存データを引き継ぐ処理は無効です。

## 8. 複数の開き方で同じ状態にする（スプレッドシート同期）

Safari とホーム画面アイコンは、保存先が別です。同じ記録にしたいときは、`sync/` フォルダの手順（`SYNC_SETUP.md`）で、Google スプレッドシートに記録を送る設定をします。
履歴はスプレッドシートに 1 操作 1 行で残るので、あとから見返せます。`sync/Code.gs` は、スプレッドシート側に貼るスクリプトです（GitHub には上げません）。

## 9. ボーナス（任意のTODO・別ポイント）

通常の予定とは別に、「この日は〇〇をする」というボーナスを出せます。ちゃんとやれたら、**通常のポイントとは別の「ボーナスポイント」**が貯まります。

- ボーナスは、通常の「全部できたら +1 ポイント」には影響しません。円グラフにも入りません。
- ボーナスポイントは、ボーナスをやるたびに、その分だけ貯まります（1 件ごとに `pts` を決められます）。
- 日付を指定して、`plans.json` の `bonus` に書きます。ボーナスのない日は、何も出ません。
- ボーナス専用のごほうびは、`bonusRewards` に書きます（通常の `rewards` とは別です）。
- 中身（`bonus` と `bonusRewards`）が空のあいだは、画面にボーナスは出ません。

```json
"bonus": {
  "2026-11-10": [
    { "id": "b1", "name": "おへやの おそうじ", "icon": "🧹", "pts": 2 },
    { "id": "b2", "name": "えいごの ほんを 1さつ よむ", "icon": "📖", "pts": 3, "memo": "よんだら おしえてね" }
  ]
},
"bonusRewards": [
  { "id": "br1", "pts": 10, "name": "ゲームの じかん 30ぷん", "icon": "🎮" }
]
```

- `bonus` のキーは `YYYY-MM-DD`。`id` は、その日の中で重複しないようにして、あとから変えないでください。
- `pts` は 1〜99 の整数、`bonusRewards` の `pts` は 1〜999 の整数です。
- 保護者画面で、ボーナスポイントの ±1 補正、0 に戻す、ごほうびを渡したチェックができます。
- スプレッドシート同期を使うと、ボーナスの記録も履歴に残り、「サマリー」シートに合計が出ます。

### 9-2. 毎日出るボーナスと、くり返すごほうび

- **`bonusDaily`**：**毎日**出るボーナスです（曜日を問いません）。`bonus`（日付指定）と同じ形で書きます。`bonus` に同じ日付のボーナスがあれば、毎日のボーナスに**追加**して表示されます。
- **`bonusRewardsRepeat`**：`true` にすると、ボーナスのごほうびを**全部クリアしたあと、同じごほうびをもう一度くり返します**。
  たとえば `10 ポイントで 10えん、30 ポイントで 50えん` なら、10・30 ポイントで 1 周目、40・60 ポイントで 2 周目、70・90 ポイントで 3 周目…となります（1 周の長さは、いちばん大きい `pts` です）。
- 保護者画面の「ごほうびを渡したら チェック」には、獲得したごほうびが 1 回分ずつ出ます（周回ごとに別々に記録されます）。
- ボーナスポイントを「0 に戻す」と、周回も最初からになり、「もらった」のチェックも外れます。

```json
"bonusDaily": [
  { "id": "bd-help", "name": "おてつだい できた", "icon": "🧺", "pts": 1 }
],
"bonusRewards": [
  { "id": "br1", "pts": 10, "name": "10えん", "icon": "🪙" },
  { "id": "br2", "pts": 30, "name": "50えん", "icon": "💴" }
],
"bonusRewardsRepeat": true
```
